# Changelog

All notable changes to this project are documented here.

## [Unreleased]

### Added

- Campaign shell: pause, a level route, checkpoints and saved progress. **Pause:** `Escape` stops the fixed step (`startGameLoop`'s `paused` option, also an argument of `advanceAccumulator`; no `handleInput`, no `update`, banked time dropped, so resuming does not replay it) while the last snapshot keeps drawing under a small overlay. Level complete pauses too, and only a level load (Reload, Next, dropdown, `1`-`9`) ends that. The overlay is React state on transitions only. **Route:** an optional `next` id on a manifest entry decides what the complete screen offers (`resolveNextLevel` in the new `src/game/session.ts`); with none, or an id the manifest lacks, there is no Next button and a line saying the route ends, instead of wrapping to `test-1`. The shipped manifest chains `test-1 → demo-decor → demo-pano → courier-1`. **Checkpoints:** optional `checkpoints: [{ position, size }]` per level, triggers like goals. Entering one makes its centre the respawn point and emits `CheckpointReached` (once, until the player leaves); a hazard respawn uses the latest one, with the payload still returning to its pad. `loadLevel` stays a pure reset; the shell re-applies a saved index with `Game::restoreCheckpoint`. **Progress:** finished level ids and the active checkpoint per level in `localStorage` (`bolts-and-volts:progress:v1`, no server). Boot starts at the first unfinished level; completing a level drops its checkpoint; `R` and Reload restart from the spawn; a *Reset progress* button clears the key. Validator, `normalizeLevelData` and `docs/architecture/level-format.md` cover `checkpoints` and `next`. Not in this change: checkpoint art, per-level music, restoring velocity/character/ability. Tests: 6 native cases (checkpoint moves the respawn point, once until re-armed, hazard respawn at the checkpoint with velocity cleared, no checkpoints still spawn, payload rule, restore after load), `tests/unit/session.test.ts`, manifest `next` and loop pause cases, `tests/e2e/session.spec.ts`.
- Instanced sprite batching. `drawScene` now pushes every sprite, in paint order and after the existing CPU cull, into a `SpriteBatch` (`src/gl/spriteBatch.ts`, no GL, unit-tested in `tests/unit/spriteBatch.test.ts`) and draws each run of same-texture sprites with one `drawArraysInstanced` instead of one `drawArrays` plus ~8 uniform writes per quad. Position, size, frame, sheet size, flip, alpha and tint are per-instance attributes (`tex.vert.glsl`), so the player tint is the player instance's own and cannot leak into a later sprite. A screen of 60 same-texture platforms is one draw call (`Renderer.getDrawStats()`, checked in `tests/e2e/renderer.spec.ts`). Context attributes are unchanged.
- WebGL context loss handling. The renderer `preventDefault`s `webglcontextlost`, the game loop stops on it and resumes on restore with a fresh clock; `Renderer.restore()` rebuilds programs, VAOs, buffers and one-time state and re-uploads every texture into the same `TextureObject`. Tested with a real loss/restore through `WEBGL_lose_context` (e2e) and a fake renderer for the loop (`tests/unit/loop.test.ts`).
- Physics broadphase: `cpp/src/sim/PlatformGrid` (uniform 4-unit grid over static platforms, built in `Simulation::loadLevel`). The vertical and horizontal resolves test only its candidates, in ascending index order with a re-query after each push, so every trace is bit-identical to the old full scan (checked against it on 600k random ticks). New native cases: a fall with 300 distant platforms lands like the same fall alone; overlapping platforms push out in index order, including a push into a platform in another cell.
- Multi-layer background rendering from level JSON (`backgroundLayers`) with per-layer parallax/scale/offset.
- Decor pipeline (`decor`) for non-colliding depth-aware visuals with per-item texture/parallax/layer controls.
- Level manifest support (`public/levels/manifest.json`) with runtime level switching and level metadata overlay.
- New demo map: `public/levels/demo-decor.json`.
- World-space background layers (`"mode": "world"` in `backgroundLayers`): a painted image placed at a fixed world rectangle (or fitted to level bounds) with optional grounded parallax, so platforms can be aligned to painted features. Parallax remains the default mode. Validator and `docs/architecture/level-format.md` updated.
- New demo map `public/levels/demo-pano.json` (pano generated by `scripts/gen_demo_pano.py` from the level's own platform coordinates).
- Level-authoring aids for placing platforms against busy backgrounds (parallax and world-space alike). `G` toggles a world-space grid (orange axes, brighter major lines), `Shift+G` cycles its spacing 1.0 / 0.5 / 0.25, `H` toggles authoring mode: a HUD with mouse world coordinates, snapped coordinates and camera view range, high-contrast platform outlines, dimmed player/particles, and a snap marker. `P` (in authoring mode) copies a platform JSON snippet at the snapped cursor position. Hotkeys are ignored with Ctrl/Meta/Alt held or while a form control is focused. Helpers in `src/lib/authoring.ts` with unit tests; Playwright coverage in `tests/e2e/authoring.spec.ts`.
- Render-only visible-rect culling: `drawScene` skips platforms (textured + debug boxes), decor (parallax-aware), goals, particles and authoring outlines that lie fully outside the camera view plus a 1-unit margin (`src/lib/culling.ts`). Physics/collision and the player sprite are untouched. `K` toggles a cull debug view: the cull rect is shrunk 2 units inside the screen and outlined in magenta, with a `drawn/total` counter HUD. Unit tests in `tests/unit/culling.test.ts`; Playwright coverage in `tests/e2e/culling.spec.ts`.
- ESLint 9 flat config (`eslint.config.js`) and `lint:fix` script.
- Structured documentation hub under `docs/`:
  - `docs/ai/`
  - `docs/plans/`
  - `docs/architecture/`

- Native simulation tests: `npm run test:sim` builds `tests/native/sim_tests.cpp` + `cpp/src/sim/Simulation.cpp` with the host compiler (doctest 2.5.3, vendored single header under `tests/native/third_party/doctest/`, MIT) and runs them; CI runs it before installing emsdk. Cases: standing doesn't sink or float, walking off a ledge starts coyote, coyote jump, jump buffer, jump cut applies once, Bolts pound (air vs ground), Volts hover gravity (only while active and airborne), goal fires once, camera X stays in bounds, switching resets the ability, long falls (3–100 units, with and without a pound) land on a 0.2-thick platform on the tick of contact, resting contact never shoves the player, jump apex heights, and replay determinism.

- Character presentation for the two-dog kit. `C` now visibly changes the player: Bolts is drawn warm bronze, Volts cool cyan, through a `u_tint` vec4 in `tex.frag.glsl` (RGB multiplier plus a 0..1 amount of the sample's own hue to drop first; a plain multiply turned the blue sheet green for Bolts). It is set only around the player draw, so platforms, decor, goals and particles stay untinted. The ability overlay (`src/components/AbilityHud.tsx`, `src/game/abilityHud.ts`) shows character, ability (Ground Pound / Hover), ready / active / cooldown and a 0..1 bar from `getAbilityCooldownPercent`, written from the snapshot to DOM refs. Three new sound effects, `ground_pound`, `hover` and `switch` (`public/*.mp3`, synthesized by `scripts/gen_sfx.py`), were silent before because `AudioManager` had no buffers for them. No physics constants changed. Tests: `tests/unit/abilityHud.test.ts`, `tests/e2e/ability-hud.spec.ts`, tint cases in `tests/e2e/renderer.spec.ts`.

- Courier entities: hazards, one payload and terminals, in the C++ sim next to platforms and goals, plus a demo level that uses all three, `public/levels/courier-1.json` ("Courier Run - Special Delivery", 4th in the manifest). A hazard overlap respawns the player at `spawn` and returns a carried payload to its pad. A hazard with `patrol: { x0, x1, speed }` paces between two x positions. The payload rides on top of the player once touched, and a level with a payload only completes while it is carried. `test-1`, `demo-decor` and `demo-pano` have none and behave as before. Volts pressing `E` at a terminal disables its `disablesHazard`; Bolts cannot. The press uses the existing ability-key edge, works while hover is cooling down, and is taken by the terminal only while overlapping an unused one. New sim events `Respawned`, `PayloadPickedUp`, `TerminalUsed` (particle bursts; no new sounds). The snapshot header grows to 20 floats (`HAZARD_COUNT`, `PAYLOAD_COUNT`, `TERMINAL_COUNT`), and the three lists are packed after the goals at 5 floats each (x, y, w, h, flag). First art is tinted quads, culled like the rest (`entities` in the `K` HUD). `normalizeLevelData` passes the arrays through, `validateLevel` checks them, and `docs/architecture/level-format.md` documents them. Tests: 7 new native cases (respawn, patrol range, carry through a jump, goal gated on carry, respawn drops the payload, terminal Volts vs Bolts, terminal vs hover on one key), `tests/unit/levelData.test.ts`, validator and snapshot cases, and an e2e pixel test for the entity quads.

### Changed

- The level-complete screen's Next no longer wraps from the last level to the first; it follows the manifest's `next`. The overlay no longer leaves the simulation running underneath. `R` now restarts the level from its spawn (forgetting its saved checkpoint) rather than only reloading the JSON.
- The frame snapshot no longer carries platforms or goals (`FrameLayout` / `FRAME`: `PLATFORM_COUNT`, `GOAL_COUNT` and `BOX_STRIDE` removed; header slots 12-13 reserved). They are static per `loadLevel`, so `SceneAssets` in `src/game/loop.ts` holds the arrays passed to it and `drawScene` reads those. The e2e wasm stub serves scene geometry as the level JSON.
- The monospace debug status line (`[BOLTS] pos: x,y | Ability: READY`) is replaced by the ability overlay, so the player position is no longer shown (the `H` authoring HUD still shows mouse and camera world coordinates). `drawScene`'s unused `character` parameter became `playerTint`. `tests/e2e/render-count.spec.ts` now watches the HUD bar change every frame instead of the position text, and the e2e WASM stub can report a character, ability state and draining cooldown.
- Simulation split out of `Game.cpp`. `cpp/src/sim/Simulation.{hpp,cpp}` owns the player body, platforms, goals, character/ability, camera and animation state, takes a parsed `LevelSpec` and includes no emscripten. `Game` is now the embind adapter (same embind methods, same snapshot). The sim reports `SimEvent`s (`Jumped`, `Landed`, `PoundImpact`, `HoverTick`, …), which `Game` turns into particles, sounds and the level-complete callback. `ParticleSystem` owns a seeded xorshift32 instead of calling the unseeded `rand()`, so a replay of the simulation is deterministic and particle flavour is off the collision path. Ability magic numbers moved to `CharacterStats` (`BOLTS_GROUND_POUND_DURATION`, `…_KEEP_VX`, `VOLTS_HOVER_KEEP_FALL`, `SWITCH_KEEP_VX`).
- Ground detection now comes from the vertical resolve (step, resolve Y, then set grounded) instead of a probe at the previous position. Takeoff and flight are unchanged, and jump apex heights are identical to before (Bolts 0.909, Volts 1.130 above the takeoff point). The changes are at the ground: landings stop exactly on the platform (they used to stop up to ~0.1 above it), the `land` sound and particles fire on the tick of contact, and coyote jumps now get the full jump strength (they were ~one gravity tick weaker than ground jumps).
- Fast vertical moves are subdivided (each substep under half of player half-height + thinnest platform half-height; one step for anything under ~15 u/s), so long falls can no longer pass, or be pushed, through thin platforms.

- Game loop out of React, one snapshot per frame, fixed step. The per-frame loop moved to `src/game/loop.ts`; `GameCanvas` no longer calls `setState` every frame (status, authoring and cull HUD text are written to DOM refs), so React re-renders only on level change, volume, hotkey toggles and level complete. `Game::captureFrame()` packs player, camera, animation, ability, platforms, goals and particles into one float buffer read through `HEAPF32` (`src/game/snapshot.ts`), replacing the per-element `getPlatforms`/`getGoals`/`getParticles` embind copies; `AnimationState.currentState` is now the `PlayerState` int and the renderer maps it to a spritesheet row. The simulation runs at a fixed 1/60 s step (up to 4 ticks per frame), so jump height no longer depends on frame pacing or hitches. Level JSON parsing moved to `src/lib/levelData.ts`, decor/background texture loading to `src/game/levelAssets.ts`, held-key input to `src/game/input.ts`. The legacy `game.js` / `createGameModule` loader paths were removed and `loadLevel` is typed (`CoreLevel`). Fixes: the HUD always showed `[BOLTS]` after `C` (stale closure), and changing the volume created a new `AudioManager` and re-registered key handlers on every slider tick. Unit tests in `tests/unit/snapshot.test.ts` and `tests/unit/loop.test.ts`; e2e stubs share `tests/e2e/wasmStub.ts`; `tests/e2e/render-count.spec.ts` asserts no per-frame React commits.
- Renderer context and canvas sizing: the WebGL2 context is now opaque (`alpha: false`), non-MSAA, without depth/stencil, prefers the discrete GPU and requests `desynchronized` presentation (one retry without it). The canvas no longer has a fixed 1280×720 backing store: it follows its CSS box × `min(devicePixelRatio, 2)` via `ResizeObserver` (`src/lib/canvasSize.ts`, `Renderer.resize`), so the world is no longer stretched on non-16:9 layouts and HiDPI screens stay sharp. The canvas is taken out of flow (`position: absolute`) so its backing-store size cannot feed back into the flex layout. In dev, a stale first StrictMode init no longer keeps running as a second game/renderer on the same canvas. The world stays 10 units across the backing-store width (no letterboxing). Unit tests in `tests/unit/canvasSize.test.ts`; renderer tests in `tests/e2e/renderer.spec.ts`.
- Draw-state hygiene: blend/depth/scissor/`UNPACK_ALIGNMENT` are set once at init, the projection is rebuilt on resize instead of per sprite, and each quad kind has a VAO instead of re-binding buffers per sprite. Authoring-overlay line widths are now constant in CSS pixels (they keep the same on-screen thickness on HiDPI).
- Red/green collision debug boxes are no longer drawn during normal play; they sit behind `Renderer.setCollisionDebug` (default off).
- Camera supports optional vertical follow + Y clamping via per-level camera config.
- Goals are read from WASM getters in the render loop instead of mirrored JS refs.
- README and AI docs now cross-link to the new docs layout.

### Removed

- Dead shader copies: `src/gl/shaders/basic.vert.glsl` / `basic.frag.glsl` (nothing imported them) and `public/shaders/*` (Vite loads GLSL via `?raw` from `src/gl/shaders/`).

### Fixed

- `createWebGL2Context` retried without `desynchronized` only when `getContext` returned null; a throw skipped the retry. Both now retry once.
- Every jump also played the `land` sound and land particles on its takeoff tick, and granted coyote time while rising, so re-pressing jump within 0.12 s of takeoff gave a double jump.
- Ground pound (and any exact landing) could eject the player sideways to a platform edge, e.g. on test-1's spawn floor (the old AGENTS.md "pound tunnels through thin floors" issue). The cause was float rounding of the resting height, which made the horizontal resolve see an overlap. Overlaps of ≤ 1e-4 now count as contact.
- Pressing jump and ability on the same tick on the ground triggered a ground pound at takeoff.
